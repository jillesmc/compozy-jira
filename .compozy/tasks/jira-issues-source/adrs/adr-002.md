# ADR-002: TypeScript on Node.js for portability

## Status

Accepted

## Date

2026-11-14

## Context

The extension is published as a GitHub Release, and installers receive exactly the generation
`compozy extension build` produced on the author's machine. A Go extension builds a native `bin` for
the build host only (`internal/extension/build_toolchain.go`), so a release built on the author's
Linux x86-64 machine would not run on macOS. It has not been verified that the installer selects a
per-platform artifact. The user chose portability (Q3 = a).

## Decision

Write the extension in TypeScript with `@compozy/extension-sdk` (pinned 0.7.0, which sets the CompozyOS floor to 0.7.0). Build with the
CompozyOS TS toolchain (`bun build --target=node` into one `dist/index.js` bundling the SDK), and run
the subprocess with `node index.js`, which requires Node.js ≥ 22 on the installer's machine.

## Alternatives Considered

### Alternative 1: Go with the `heartbeat-source-go` template

- **Description**: mirror `extensions/forge/github` directly in Go.
- **Pros**: an existing template; reference code in the same language; no runtime dependency.
- **Cons**: a single-platform artifact; macOS users cannot run the first release.
- **Why rejected**: it fails the portability goal (US-009.AC-2).

### Alternative 2: Go with per-platform release artifacts

- **Description**: build and publish linux/darwin × amd64/arm64.
- **Pros**: native and portable.
- **Cons**: depends on installer support for per-platform assets, which is unverified, and needs a
  cross-build pipeline.
- **Why rejected**: unverified dependency and more delivery work, for no user-visible gain over Node.

## Consequences

### Positive

- One artifact runs on Linux and macOS (x86-64 and arm64).
- The SDK registration (`extension.heartbeatSource`) auto-adds `heartbeat.source` to capabilities.

### Negative

- Node.js ≥ 22 must be installed where the extension runs.
- There is no TS heartbeat template, so the project starts from `tool-provider-ts` and replaces the
  tool with a source.

### Risks

- An SDK minor bump raises the compatibility floor stamped at build. Mitigation: pin the SDK version
  and bump it deliberately with a release note.

## Implementation Notes

- `subprocess: { command: "node", args: ["index.js"] }`.
- Build script: `tsc --noEmit && bun build src/index.ts --target=node --outfile=dist/index.js`, as in
  the template.
